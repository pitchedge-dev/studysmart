# StudySMART mix-and-match AI routing — 2026-11-25

Before this change, every category shared one fallback order (Gemini →
Groq → OpenRouter → …). Now each job leads with the provider best suited
to it, and the order differs per category. 18 providers are wired in
total (12 from before + 6 new OpenAI-compatible signups from the API
hunt: SiliconFlow, AIML API, Hugging Face, Moonshot, Zhipu,
Qwen/DashScope). A provider with no key set is skipped silently, so
the app works exactly as before with only the Gemini key set.

> Update 2026-11-26 — Pollinations 2nd in every text chain + no
> simplified retry on timeouts + DeepSeek billing-dead
> (commit: fix-pollinations-early).
>
> The tables below now show the RESOLVED try order after this change.
>
> Why: the 2026-11-26 16:52 outage (Vercel logs, one POST
> /api/generate, 50.4s, 503) proved the interleave alone was not
> enough. Gemini 3.8-flash timed out at its 25s first cap, the
> timeout→simplified retry then burned ~15s timing out again on the
> same hanging model, DeepSeek failed fast on "Insufficient Balance"
> (its 30-day grant is exhausted — billing-dead, alongside Moonshot /
> AIML / SambaNova), and Cohere timed out at its 20s cap. Pollinations
> was NEVER tried — no attempt log, no external call.
>
> Two changes follow: (1) Pollinations — the only no-key provider —
> now sits SECOND in every text chain, right after the primary, so it
> is tried while time remains; if its POST works it saves the
> request, and if it fails fast little time is lost. (2) A full-shape
> attempt that TIMES OUT no longer gets a simplified retry on the
> same model — a hanging model times out again, and the 15s it burned
> is the wall's scarcest resource. The simplified retry survives only
> for NON-timeout failures, where the model answered but the shape
> was wrong.
>
> Caps unchanged: first attempt 25s, every later attempt 20s, wall
> 50s. Honest worst case: Gemini hangs 25s AND Pollinations hangs
> 20s = 45s, leaving 5s for one last try — the wall still limits
> what follows.

> Update 2026-11-26 — INTERLEAVED chains + billing-dead deprioritization
> + longer caps (commit: fix-chain-interleave).
>
> The tables below now show the RESOLVED try order — the order models
> are actually attempted when every key is set. The code lists in
> `lib/providers.ts` (CATEGORY_SPECS) are still written grouped by
> provider (all four Gemini models together, both Groq models together,
> …), but `resolveSpecs()` interleaves them round-robin by provider:
> first model of each provider, then second model of each, and so on.
> With fewer keys set, the providers without a key drop out and the
> relative order of the rest is unchanged.
>
> Why: the 2026-11-26 12:33 outage (Vercel logs, one POST /api/generate,
> 50.44s, 503) proved a grouped order fails — all four Gemini models
> were tried first (overload, then three 12s timeouts), Moonshot / AIML
> / SambaNova then failed fast on billing, and the 50s wall ran out with
> DeepSeek and Pollinations never tried. Interleaving keeps the provider
> priority (the first provider in each list still goes first) but one
> provider's outage can no longer eat the wall.
>
> The same logs proved Moonshot, AIML API and SambaNova BILLING-DEAD
> (free credits exhausted / card required), so they now sit AFTER the
> live providers in every chain — they fail fast when reached and cost
> nothing, but must never sit ahead of a live provider. They are NOT
> deleted: if a balance is ever restored, move them back up.
>
> DeepSeek was ALIVE that morning (its base URL was fixed 2026-11-26
> — it 404d before — and its 30-day grant was valid until ~Dec 25,
> 2026), so it was reached early while the grant lasted. By that
> afternoon the grant was exhausted ("Insufficient Balance", Vercel
> logs 16:52:40 CST) — DeepSeek is now BILLING-DEAD and sits after
> the live providers; see the update above. Pollinations was MID-CHAIN
> then — a no-key safety net that is never reached cannot save a
> request — and is now SECOND in every text chain. GitHub Models sits
> after Pollinations and only activates once GITHUB_TOKEN is set
> (still unverified).
>
> Caps (lib/generationBudget.ts): first attempt 25s, every later
> attempt 20s — a healthy provider needs ~15–25s for a full-shape
> guide (2-module guide measured at 14.2s; full guides ~25–40s), so
> the old 12s cap could not succeed even on a healthy provider.
> Fewer, longer attempts rather than many short ones that cannot land.
> The timeout→simplified retry described in the original version of
> this block was REMOVED the same day (see the update above): a
> hanging model times out again on the smaller shape.

> Update 2026-11-26: Vercel AI Gateway was removed from every chain —
> its free credits require a credit card on file (which this app never
> adds) and its account was suspended for insufficient balance, which
> took live generation down (2026-11-25). The tables below no longer
> list it. The same change fixed DeepSeek's base URL (it was missing
> /v1, so every DeepSeek call 404d) and made billing errors retryable
> instead of terminal, so one provider's billing demand can never
> surface as the generation failure again. Moonshot / AIML / SambaNova
> / Cohere keys are set in Vercel but were never live-tested — if
> generation still fails after this change, test those keys one by one.

Hard limits respected everywhere: Groq 1,000 req/day per model (deepest
free allowance — leads high-volume work); Cerebras 1M tokens/day BUT
8,192-token context cap (short jobs only, never full guides); DeepSeek's
5M-token 30-day grant is EXHAUSTED (billing-dead since 2026-11-26 —
"Insufficient Balance"); Novita $1 one-time credit (last among keyed
providers in each list); Pollinations is the no-key safety net, now
SECOND in every text chain rather than last; GitHub Models key-gated
and unverified (after Pollinations, never first). No key value is
recorded anywhere.

Model IDs are per provider docs, Nov 2026 — re-check a console if a
model 404s; the chain treats a retired ID as retryable and moves on.
